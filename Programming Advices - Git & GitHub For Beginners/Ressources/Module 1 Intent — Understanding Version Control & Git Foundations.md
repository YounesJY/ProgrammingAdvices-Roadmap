# Module 1 Intent — Understanding Version Control & Git Foundations

## 1. Module Purpose

Build the mental model of Git from zero. Commands come later — this module establishes **how to think about Git**, not how to type it.

The rest of the course depends on this foundation. If this is clear, the rest becomes easy.

---

## 2. Module Outcomes

By the end of Module 1, the learner will:

| #   | Outcome                                        |
| --- | ---------------------------------------------- |
| 1   | Understand the real problem Git solves         |
| 2   | Clearly differentiate Version Control systems  |
| 3   | Understand why Git is distributed and powerful |
| 4   | Stop feeling confused about Git terminology    |
| 5   | Think in snapshots, not files                  |
| 6   | Understand the 3 states of Git                 |
| 7   | Visualize commits, branches, and HEAD          |
| 8   | Set up Git correctly on the machine            |

---

## 3. What This Module Is Doing Differently

- Not command-first — **mental-model-first**
- Terminology is resolved *before* usage
- Core abstractions introduced early: snapshots, 3 states, commits, branches, HEAD
- Setup is the last step, not the first — understanding precedes configuration

---

## 4. Why This Ordering Matters

Every later topic in the course (branching, merging, conflicts, GitHub, fixing mistakes) is a consequence of the model built here. Misunderstanding snapshots or the three states produces the exact beginner confusion this course targets: fear of branching, accidental commits, detached HEAD panic, force-push disasters.

Get the model right in Module 1 → those later topics become mechanical.
