# What is Version Control?

## 1. Introduction

The previous lesson established the problem: managing changes without structure leads to chaos. **<mark><u>Version Control</u> is the solution</mark>**.

---

## 2. The Concept

<img src="https://uploads.teachablecdn.com/attachments/299bdb8294234cee8bab56d2071e38d0.png" title="" alt="" width="405">

Version Control is a system that:

| Capability              | What it does                           |
| ----------------------- | -------------------------------------- |
| Track changes           | Records every modification to the code |
| Save versions over time | Preserves each state of the project    |
| Go back                 | Restores any previous version          |
| Understand change       | Shows what changed and when            |

Instead of manual file copying, version control does this **<mark>automatically and intelligently</mark>**. It records:

- **<mark>What</mark>** changed
- **<mark>Who</mark>** made the change
- **<mark>When</mark>** it happened

The result: your project has a **<mark><u>history</u></mark>**.

---

## 3. Mental Model

<img src="https://uploads.teachablecdn.com/attachments/e4fd622cdbba42ccb9e68b02b41140fd.png" title="" alt="" width="402">

### 3.1 Time machine for your code

```
Version 1 → Version 2 → Version 3 → Version 4
```

You can move forward to new changes, go back to old versions, and compare points in time. Each version is saved safely.

### 3.2 The annual photo

Think of taking a photo of yourself every year:

<img src="https://uploads.teachablecdn.com/attachments/66e780a24153405caf2d8b3a75d417f5.png" title="" alt="" width="555">

| Photo concept                  | Version control equivalent |
| ------------------------------ | -------------------------- |
| Each photo = a moment in time  | Each commit = a snapshot   |
| Go back and see how you looked | Check out an old version   |
| Compare different years        | Diff two commits           |
| Nothing is lost                | Full history preserved     |

History becomes **<mark>clear and easy to <u>explore</u></mark>**.

---

## 4. The Insight

Version Control is **<mark><u>not just</u> about saving files</mark>** — it is about **<mark>understanding <u>evolution</u></mark>**.

You don't just see the code. You see **<mark>the story of the code</mark>**.

---

## 5. Common Confusion

<img src="https://uploads.teachablecdn.com/attachments/43f719dca82342d6a4e8c5d2d6b038a8.png" title="" alt="" width="403">

> "It's just backup."

| Backup               | Version Control              |
| -------------------- | ---------------------------- |
| Saves copies         | Tracks changes               |
| No diff              | Shows differences            |
| Single-user mindset  | Enables collaboration        |
| No history of intent | Enables safe experimentation |

Backup answers "what did the file look like?" Version control answers "how did the code get here?"

---

## 6. The Rule

> **<mark>Version Control</mark> = <mark>tracking change</mark>, not just saving files.**

---

📌 **Summary**

| Question                  | Answer                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| What is Version Control?  | A system that tracks changes, saves versions, enables rollback, and records what/who/when |
| What is the mental model? | A time machine for code — or an annual photo of the project                               |
| What does it record?      | What changed, who changed it, when                                                        |
| Is it just backup?        | No — backup saves copies; version control tracks evolution and enables collaboration      |
